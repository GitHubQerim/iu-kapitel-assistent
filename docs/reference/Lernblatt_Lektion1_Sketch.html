1.1 INFORMATIONSTECHNIK (IT) S. 13–14

IT = konkreter Einsatz elektronischer Geräte für Erhebung + Verwendung von Daten durch Menschen oder Maschinen
  • hat immer einen Anwendungsbereich in realer ökonom./sozialer Umgebung: Einzelperson, Firma, Abteilung
  • braucht (elektron.) Geräte, meist fest in Arbeitsorganisation eingebunden → orientiert an Geschäftsprozessen
  • privat: E-Mail, Chat … · Stichworte: „Industrie 4.0“, „Wirtschaft 4.0“
Daten = formalisierte Darstellung von Sachverhalten/Konzepten/Anweisungen für Übertragung, Speicherung, Verarbeitung · Information = die Bedeutung, die den Daten aufgrund von Konventionen beigelegt wird · Signal = Darstellung von Daten durch räuml./zeitl. Veränderung physikal. Größen
Klausur-Falle Der Name „Informationstechnik“ ist eigentlich irreführend: IT befasst sich gar nicht mit Informationen, sondern mit formalisierten Darstellungen (= Daten)!

Informationsverbund (BSI) S. 14

= konkrete Ausprägung der IT = alle technischen + alle organisatorischen Komponenten des Anwendungsbereichs · technische Komponenten = IT-Infrastruktur
technisch Abb. 2
Hardware — Rechengeräte (PC, Tablet, Smartphone, Phablet) · Netzwerkgeräte (Switch, Router) · Peripherie (Tastatur, Drucker, Kamera) · Betriebsgeräte (USV)
Software — Firmware · Betriebssystem · Anwendungssoftware/Apps
Bauliche Einrichtungen — Räume (Klimatechnik) · Gebäude (Zutrittskontrolle) · Standorte
organisatorisch Abb. 4
Institution — EU-Verordnungen · Gesetze (Bund, Länder) · Standards (ISO, DIN)
Struktur — Geschäftsführung · Betriebsrat · Datenschutzbeauftragter
Personal — Mitarbeiter: Anzahl + Qualifikation für Planung, Wartung, Betrieb
↳ Aufgabe der Informationssicherheit: alle diese Komponenten angemessen schützen

Boot & UEFI S. 15

UEFI (Unified Extensible Firmware Interface) = Schnittstelle Firmware ↔ OS, ersetzt BIOS · modular erweiterbar: Netzwerkmodul für Fernwartung, DRM, BIOS-Emulation, Bootloader · Secure Boot: nur ausdrücklich erlaubte Dateien dürfen das OS starten
Merksatz 1.1 IT = Geräte + Daten + Anwendungsbereich · Informationsverbund = technisch (Hardware/Software/Bau) + organisatorisch (Institution/Struktur/Personal) · Netz: MAC ↔ IP ↔ Port, TCP zuverlässig / UDP schnell

NETZWERKE S. 15–16

Netzwerkgeräte unterstützen 1lokale Netze einer Technologie (LAN, WLAN, Bluetooth) oder 2Netzwerke von Netzwerken → heute fast immer TCP/IP

LAN = Ethernet (IEEE 802.3), kabelgebunden

  • MAC-Adresse: 48 Bit, hexadezimal, z. B. 00-80-41-ae-fd-7e · ff-ff-ff-ff-ff-ff = Broadcast (an alle)
  • Daten in Rahmen (Frame) mit Sender- + Empfänger-MAC → an alle geschickt, nur benannter Empfänger nutzt ihn
  • FCFS (First-Come-First-Served): Medium frei? → senden (ggf. nach zufälliger Verzögerung + erneuter Prüfung) → sendet noch jemand? → abbrechen
  • Hub: sternförmig, CAT-Kabel, RJ-45 → gibt stumpf an alle weiter · Switch: wertet Adressen aus → nicht jeder kriegt alles
WLAN (IEEE 802.11) = LAN ohne Kabel · Teilnehmer senden Beacons („ich bin da“) · Ad-hoc-Netz oder Infrastruktur-Netz über Access Point · Norm regelt Frequenzen, Tempo, Senderauswahl, Roaming (Wechsel zu anderem AP)  ·  Bluetooth: urspr. Nahbereich (Piconets), Version 4.x konkurriert mit WLAN

TCP/IP-Protokollfamilie S. 16–18 Abb. 3

= Netzwerktechnik mit übergeordneter Adressierung, überwindet Grenzen einheitlicher Netze (z. B. Ethernet) · Protokoll = Vereinbarung, die Kommunikationsverhalten syntaktisch + semantisch festlegt
  • IP-Adresse (v4): 32 Bit → 4 Zahlen 0–255, z. B. 195.247.86.5 · DNS übersetzt Name → IP (www.iu.de → 78.137.97.49), Tabelle liegt auf DNS-Servern; jeder Verbindungswunsch: erst DNS, dann Router
  • Router = fundamentale Bausteine, realisieren IP: schieben Datagramme per Netzadresse durch Zwischennetze — verbindungslos: Weg zu komplex? → Datagramm vernichtet, Empfänger erfährt nichts, Sender nur „halbherzig“ informiert
  • Router sehen IP + Ports → oft zugleich Firewall (Regeln sperren Ports/IPs) · Wort urspr. = Trennwand gegen Feuer (Auto)
TCP
zuverlässig, verbindungsorientiert · Sender + Empfänger über Ports fest gekoppelt, vorher vereinbart · verlorene Datagramme werden erneut geschickt
UDP
verbindungslos, keine Vollständigkeitsgarantie · Bild/Ton, VoIP: Verbindungsauf-/abbau muss fehlerfrei, Sprachpakete dürfen verloren gehen (Tempo > Vollständigkeit)
Anwendungsprotokolle: FTP Dateien · HTTP Webseiten · SMTP E-Mail an Server · DNS Name → IP · VoIP Telefonie  → urspr. ohne Sicherheit gebaut ⇒ gesicherte Varianten: FTPS/SFTP · HTTPS · DNSSEC · DNS over HTTPS („S“ = secure)

Randbemerkung: MAC & Hash S. 16

3× MAC — nicht verwechseln! MMedia Access Control → die Adresse oben  ·  MMandatory Access Control → Zugriffsrechte (kommt später)  ·  MMessage Authentication Code → prüft Authentizität + Integrität von Nachrichten
Hash-Funktion: Eingabe beliebiger Länge → Ausgabe (Hashwert) fester, kurzer Länge; dient als Prüfsumme. Bsp.: Quersumme immer wieder bilden → einstellige Zahl → einzelne falsche Ziffer wird erkannt. Kryptografische Hashfunktion zusätzlich: praktisch nicht umkehrbar

1.2 SICHERHEIT & SCHUTZ S. 23–25

Sicherheit = Ausmaß der Bestimmtheit + Gewissheit zukünftiger Umstände = Erwartungssicherheit
  • auf die Zukunft gerichtet · an den Beobachter gebunden · relativ: gilt nur für Zeithorizont, Umgebung, Bedingungen
  • Mensch hat Konzept der Zukunft, will sie wissen/bestimmen → Umgang = Intuition + Wahrscheinlichkeit → manchmal Risiko eingehen
  • nie absolut (Blitzeinschlag!) → Störungen nur hinreichend unwahrscheinlich (Vergleich: Lottogewinn) → es geht immer um den Umgang mit Restgefahren
Security
Sicherheit gegen Einwirkungen → „Immunität“ · meist Voraussetzung für Safety → Vorrang · Fokus des Skripts
Safety
Sicherheit der Auswirkungen → „Isolation“ · z. B. Normen für Software in der Luftfahrt
↳ im Deutschen beides nur „Sicherheit“ ⇒ Sicherheit ≠ Sicherheit (Security != Safety)
Schutz = alles, was ausdrücklich der Erhöhung der Sicherheit dient · fördert Bestimmtheit/Gewissheit · Maßnahmen sind per Definition präventiv (zukunftsgerichtet): psychologisch · technisch · organisatorisch

Persönliche Schutzbereiche S. 25 Abb. 7

Menschen schließen sich zu Gemeinschaften zusammen → erwarten garantierten Schutz der Person, abgestuft nach Sphären:
Intimsphäre — Sexualität, Krankheiten, Gefühle, Gedankenwelt → möglichst absolut geschützt
Privatsphäre — häuslicher Bereich + Bereiche nur für Nahestehende; auch Interaktion mit Partner in der Öffentlichkeit → große Sicherheit, nur sehr restriktive Ausnahmen
Individualsphäre — frei beobachtbares Leben, öffentl. + berufl. Wirken → trotzdem kein sicherheitsfreier Raum: Sicherheit der Beziehungen zur Umwelt
Rechtsgrundlage Allgemeines Persönlichkeitsrecht (Grundgesetz, Art. 2) = absolutes + umfassendes Recht auf Achtung und Entfaltung der Persönlichkeit → Anspruch auf Sicherheit in allen drei Sphären

1.3 DATENSCHUTZ ALS PERSÖNLICHKEITSRECHT S. 26–27

Begriffs-Falle „Datenschutz“ müsste eigentlich Schutz von Daten heißen — meint in DE aber den Schutz des Menschen vor seiner Verdatung ⇒ treffender: „Verdatungsschutz“

Volkszählungsurteil 1983 — 5 Kernaussagen

  • 1Recht auf informationelle Selbstbestimmung (Art. 2 Abs. 1 i. V. m. Art. 1 Abs. 1 GG): jeder bestimmt grundsätzlich selbst über Preisgabe + Verwendung seiner Daten
  • 2bei automatisierter Verarbeitung gibt es kein „belangloses“ Datum — alle persönl. Daten unter GG-Schutz, sensibel oder nicht
  • 3Bürger müssen wissen: „wer was wann und bei welcher Gelegenheit“ über sie weiß → Aufklärungspflichten · Vorrang der Selbstauskunft (Grundsatz der Direkterhebung: erst den Bürger fragen, dann Dritte)
  • 4Einschränkungen nur mit ausdrücklicher gesetzlicher Grundlage — so konkret wie möglich + Aufklärungs-, Auskunfts-, Löschungspflichten
  • 5strenge Zweckbindung: nur für konkreten Zweck; Sammeln „auf Vorrat zu unbestimmten Zwecken“ unzulässig
Definition Datenschutz = Schutz natürlicher Personen bei Erhebung + Verwendung von Daten, die sie betreffen — Definition von damals, gilt bis heute
Schweiz: auch juristische Personen geschützt · Österreich + Dänemark früher auch, seit DSGVO nur eingeschränkt
personenbezogene Daten = eindeutig oder zumindest mittelbar einer natürl. Person zuordenbar: Name, Kennnummern, Standort, Online-Kennungen, physische/physiolog./genetische/psychische/wirtschaftl./kulturelle/soziale Merkmale · Betroffener = die bestimmte/bestimmbare Person · Verantwortlicher = Institution, die erhebt/verwendet
BVerfG 27.02.2008 → „IT-Grundrecht“ Allg. Persönlichkeitsrecht umfasst das Grundrecht auf Vertraulichkeit + Integrität informationstechnischer Systeme
heimlicher Zugriff auf System mit „Einblick in wesentliche Teile der Lebensgestaltung“ → nur in ganz wenigen Ausnahmen · gilt für Smartphones, PCs, Netze, gesamtes Internet · wirkt unmittelbar auf Schutz der Daten, nur mittelbar auf Datenschutz → Brücke zur IT-Sicherheit

1.4 IT-SICHERHEIT S. 28–29

Sicherheit eines Informationsverbunds = Ausmaß des voraussichtlich 1störungsfreien + 2gefahrenfreien Betriebs
  • 1Ausmaß störungsfreier Betrieb = Verfügbarkeit · Störung ohne Gefährdung → nur Zuverlässigkeit · hängt an Hardware-Qualität (Überlast, Materialversagen) + Software (strenger Entwicklungsprozess, Normen z. B. Luftfahrt = Safety)
  • 2Gefahr = jeder Sachverhalt mit negativen materiellen/immateriellen Auswirkungen
Definition (pragmatisch) IT-Sicherheit = Vorhandensein von Vertraulichkeit, Integrität und Verfügbarkeit in einem geplanten Ausmaß · Schutzziele = Aussagen über Sicherheitsniveaus, die erreicht werden sollen
Vertraulichkeit: Daten nur Befugten bekannt; Funktionen nur von Befugten genutzt · Schaden durch Bekanntwerden?
Integrität: Daten richtig, vollständig, aktuell — oder erkennbar nicht; Funktionen verlässlich — oder erkennbar nicht · Schaden/Fehlentscheidung durch Manipulation?
Verfügbarkeit: Daten + Funktionen dort/dann zugänglich, wo/wann Befugte sie brauchen · Prozess blockiert? gesetzlich gefordert?
Authentizität (wirklich der behauptete Nutzer) + Nicht-Abstreitbarkeit (non-repudiation) → Spezialfälle der Integrität · Ziele nicht unabhängig: mehr Vertraulichkeit kann Verfügbarkeit senken! · IT-Sicherheitsmanagement = Prozess: laufend Ist vs. Soll → Maßnahmen → Annäherung an Soll

1.5 ABGRENZUNG S. 30–31

Datenschutz
schützt die (natürliche) Person · garantiert informationelle Selbstbestimmung · Frage: darf überhaupt erhoben/verwendet werden? · nur personenbezogene Daten · IT-Einsatz nachrangig
IT-Sicherheit
schützt alle Daten eines Informationsverbunds, personenbezogen oder nicht · Frage: was tun, damit Erhebung/Verwendung sicher ist? · vor unberechtigter Änderung + unbefugter Kenntnisnahme · Hauptaugenmerk: Zuverlässigkeit
Überschneidung Patientendaten der Praxis: Datenschutz (Gesetz) und IT-Sicherheit (Berufsordnung → Eigeninteresse des PI) → oft dieselben Maßnahmen erfüllen beides
Zielkonflikt Login-Protokolle der Mitarbeiter: IT-Sicherheit will immer erheben + fast unbegrenzt aufbewahren — aber = pbD → Erhebung grundsätzlich erst mal nicht statthaft
